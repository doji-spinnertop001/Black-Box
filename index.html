What is black-box penetration testing?

Black-box penetration testing is a security assessment where the tester is given no internal information about the target — no source code, no network diagrams, no credentials. The engagement starts exactly where an external attacker would: a domain name, an IP range, or a public-facing application. Everything else has to be discovered.

This mirrors the real threat model most organizations care about most: someone with no insider access trying to get in. Because the tester has to enumerate, fingerprint, and map the attack surface from scratch, black-box testing is slower and less exhaustive than white-box testing — but it's the most realistic simulation of an outside compromise.

How a black-box engagement runs

Reconnaissance

Passive and active information gathering — DNS, WHOIS, subdomains, exposed services — with no interaction that would tip off the target yet.

Scanning & enumeration

Port scanning, service fingerprinting, and directory/content discovery to map what's actually reachable and running.

Vulnerability analysis

Matching discovered services and endpoints against known weaknesses — misconfigurations, outdated software, injectable input.

Exploitation

Carefully attempting to validate findings are real and exploitable, within the engagement's authorized scope.

Reporting

Documenting what was found, how it was found, its impact, and how to fix it — the actual deliverable of any engagement.

Core skill areas

Network recon

Host discovery, port scanning, and service fingerprinting across a target's exposed surface.

Web application testing

Finding injection points, auth flaws, and logic errors in public-facing apps and APIs.

OSINT

Gathering publicly available information that expands or confirms the attack surface.

tools / sqli

SQL Injection

SQL injection (SQLi) is a vulnerability that occurs when user-supplied input is inserted into a SQL query without proper sanitization or parameterization, allowing an attacker to alter the query's logic. Instead of the input being treated purely as data, part of it gets interpreted as SQL code — letting an attacker read, modify, or delete data the application never intended to expose, and in some cases execute commands on the underlying database server.

Why it happens

Raw string concatenation builds the query directly from unvalidated user input instead of using parameterized statements.

What it enables

Unauthorized data access, authentication bypass, data tampering, and in severe cases full database or host compromise.

How it's prevented

Parameterized queries, input validation, least-privilege database accounts, and web application firewalls.

Definition only — no payloads or exploitation code are included here. The Lab tab has a sandboxed target where sqlmap can be used to learn detection mechanics safely.
tools / nmap

Nmap

Nmap (Network Mapper) is an open-source tool used to discover hosts and services on a network. It works by sending specially crafted packets to target hosts and analyzing the responses — determining which hosts are up, which ports are open, what services and versions are running, and often what operating system a host is likely running. It's typically the first tool used in the scanning phase of a black-box engagement, turning a bare IP or domain into a map of reachable services worth investigating further.

Minimal example — python-nmap (not the CLI)
import nmap

scanner = nmap.PortScanner()
scanner.scan('scanme.nmap.org', '22-443')

for host in scanner.all_hosts():
    print(host, scanner[host].state())
    for proto in scanner[host].all_protocols():
        ports = scanner[host][proto].keys()
        for port in ports:
            print(f"  {port}/{proto}: {scanner[host][proto][port]['state']}")
python-nmap is a wrapper around the Nmap binary — it still requires Nmap installed on the system. Only scan hosts you own or are explicitly authorized to test.
